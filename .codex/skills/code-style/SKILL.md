# 代码风格

根据改动语言阅读对应指南，先查看同模块用法和生效配置。公共 API、框架回调、序列化字段和命令行参数沿用已有外部契约；内部命名遵循本技能。

## 执行流程

1. 查看实际语言配置、同类符号与调用方。格式配置以根 `.editorconfig` 为准，构建与检查入口见 `AGENTS.md`。
2. 函数名表达动作或返回结果，变量名表达所存内容。集合、数量、索引和对外编号分开命名；裸数值的单位会影响使用时写入名称。
3. 重命名时追踪 Kotlin 命名参数、Java 访问器、序列化、反射、资源键和命令行调用；对外契约不随内部重命名隐式变化。
4. 使用卫语句减少嵌套，保留必要的边界校验；完成后运行本次受影响范围的既有检查，继承未受影响的历史验证。

## 控制流与注释

- 函数入口先检查真实前置条件，不满足时立即返回或抛出明确错误；主路径保持扁平。
- 最大嵌套深度不超过 3 层，不计类和函数自身。超过 3 个分支的 `if-else` 链改用语言适用的分支结构。
- 不为每一步重复防御；添加兜底前确认存在真实可达的失败路径。清理本次改动中失效、重复或无人使用的代码。
- 注释使用简体中文，中英文之间留一个空格；用目标语言原生单行注释语法，同段最多 2 行。只说明意图、约束和边界，不记录修改流水账。
- 架构、依赖、协程调度和错误传播继续遵守 `AGENTS.md` 的项目约束。

## 完成与维护

项目特例记录到对应语言指南，避免在 `AGENTS.md` 重复维护风格正文。新增实际语言时再增加相应指南和索引。

`.codex/skills` 为主源；修改前核对镜像与同步基线，修改后执行 `python scripts/build_support/sync_skills.py --sync`，再执行 `--check`。技能或文档变化按链接、规则完整性和镜像一致性验证；代码变化按实际影响运行现有检查。
